# Mac 首版支持范围草案

状态：首批架构、分发渠道及 SDR 范围已确认；其余能力待验证，未授权正式开发。2026-09-24。

用户已确认首批 Apple Silicon、独立安装包、SDR 三项范围；表中其余项仍为建议或待验证，不是已经承诺的兼容性列表。不替代双平台支持契约议题；Windows x64 实机验证按用户决定暂缓。

| 项目 | 建议 | 证据或待办 |
|---|---|---|
| 首批机器 | 先支持 Apple Silicon；Intel 留待有机器后验证 | 当前仅 M4 Pro 有真实样片；不能泛称所有 M 系列均通过 |
| 系统版本 | 暂不发布最低版本承诺 | 当前仅 macOS 26.4 实测；编译目标 macOS 13 不是兼容性验收结论 |
| 分发 | 首批使用独立安装包，暂不做 Mac App Store 上架 | 签名、公证和安装测试属于获批后的正式交付；具体账号/签名条件尚未检查 |
| 色彩 | 首版只承诺 SDR，HDR 留待专项验证 | 尚无色彩测试图和 HDR 实测；SDR 也须正式验收，不默认 HDR 映射正确 |
| 输出 | 保留用户要求的 12 预设和自定义；运行前检查实际能力，不可用选项说明原因 | 已补验 1920×1080、1080×1920 各 30 秒，双文件完整解码通过；加上既有 1280×720，仍不能据此承诺 4K |
| 帧率 | 目标 30fps，先区分采集时间戳与最终输出帧率 | 实验屏幕非稳定 30fps；固定帧率要求及重复帧策略待决，不暗中变更同步目标 |
| 格式 | 优先评估 MP4 + H.264，有声模式 AAC | 当前组合有样片证据；硬件加速是否实际启用尚未证明 |
| 性能不足 | 开始前明确报错并建议降低尺寸；未经验证不静默切换双路软件编码 | 正式能力预检和故障处理尚未实现；录制中按已确认的中断保存语义处理 |
| 同步 | 保留短录 ±200ms 目标 | 相机/麦克风有真人证据，屏幕绝对同步仍有缺口；不要求 30 分钟长录 |

## 接下来验证什么

- 主用横竖 1080 尺寸已补验实际输出、三个抽样帧的四角/网格比例及双视频保存；竖屏开头出现 216.667ms 帧间隔，须明确帧率策略并在正式验收中处理。无需重复相同尺寸短录。
- 验证提词正文穿透、把手响应和窗口移动期间排除；自动移动已有局部证据，不冒充鼠标交互验收。
- 屏幕绝对同步需可标定参考；当前闪白/短音结果保留为探索性证据，不把检测数值直接设成补偿量。
- 缺少旧版 macOS、Intel、外接显示器环境的项目明确记为未测；最终确认时逐项决定补验或限制支持范围。

## 用户已确认的三项产品范围

1. 首批只覆盖 Apple Silicon，Intel 延后。
2. 首批使用独立安装包，Mac App Store 上架延后。
3. 首批只做 SDR，HDR 延后。

以上选择只确认方案范围，不授权正式开发。所有正式开发仍须另交最终方案、限制和验收清单，由用户明确批准。

## 帧率处理建议（待最终确认，不代表已实现）

建议首版输出固定 30fps，便于后续剪辑；采集和音频仍按共同的真实时间线对齐。采集暂时没有新画面时，可重复上一帧补齐输出时间点，不把视频加速，也不拉伸音频去追逐帧数。

固定 30fps 只保证文件的帧时间间隔，不代表每秒得到 30 张不同的新画面。当前竖屏开头约 217ms 的空档即便补帧仍会表现为画面短暂停住，不能靠补帧将其标记为性能验收通过。正式验证须分别检查输出帧率、实际采集间隔、重复帧数量和音画同步。

正式实现的准备阶段应确认必需采集源已有可用数据；不得仅调用启动接口就切换为“录制中”。最早可见画面、音频和用户看到的开始状态仍遵守统一会话时间线，不单独裁剪其中一路以隐藏启动延迟。

这项建议尚未改变已确认的短录同步目标，也未授权正式开发；最终确认材料应让用户同时看到“文件固定帧率”与“实际运动流畅度”的区别。
