# 第一期开发前评审清单

状态：准备中，未授权正式开发。更新：2026-09-24。

用户要求：正式开发之前必须得到明确确认。“继续”、同意一项产品建议或参与临时实验，都不等于同意开始正式开发。

## 已确认范围

- 本地极简录制场景：线框、提词、可选摄像头及控制条；设置就近浮层展示。
- 一个显示器内固定矩形区域；顶部拖动、四角等比例缩放。倒计时至停止锁定区域，提词可独立移动且正文穿透。
- 12 个输出尺寸预设及自定义；默认 1080×1920。菜单选项不等于原生支持能力已验证。
- 屏幕和摄像头独立视频，自身辅助窗口不得录入；有声模式下同一麦克风音源写入两份文件，可主动选择静音。
- 设备故障结束整次录制，尽力保存；正常保存、故障中断、部分保存和失败分别提示。倒计时可取消，退出有保存保护。
- 方案覆盖 macOS 和 Windows，允许分批开发和发布；采用 Tauri 2、React、TypeScript、Rust，无服务器。
- 不要求 30 分钟长录验证；第二期工作台、视频库、AI、字幕、剪辑、云同步不进入本期。

## 证据与缺口

| 项目 | 当前证据 | 还不能承诺 |
|---|---|---|
| Mac 原生双视频 | M4 Pro / macOS 26.4，AppKit 临时实验完成短录、连续三次、独立文件与解码检查 | 不能推广到全部 Mac、正式 Tauri 程序或全部预设 |
| 辅助窗口排除 | 固定窗口配置的参考图抽帧未见自身浮窗 | 移动、新建窗口、穿透交互的完整验证 |
| 同步 | 两次真人拍手测得相机/麦克风短录偏差区间均在 ±200ms 内 | 屏幕与物理事件同步；长期漂移 |
| 显示坐标 | 当前内建屏 2 倍缩放；既有 1280×720 样片三帧网格测量符合 960×540 点区域的等比例映射 | 其他尺寸/区域、外接混合 DPI 和显示模式变化 |
| 帧率及输出尺寸 | 旧实验屏幕固定输出 1280×720，屏幕平均帧率随样片变化，相机 1920×1080 约 30fps | 固定 30fps、12 个尺寸全部可用、4K 编码性能 |
| 浏览器交互 | 独立原型及源码检查，用户已确认核心规则并补充尺寸需求 | 本轮浏览器自动化实测尚未完成，不能作为原生捕获证据 |
| Windows | 官方 API 路径已研究；本机发现挂起的 Parallels Windows 11 ARM 虚拟机（4 CPU、6GB 内存、虚拟显卡） | 未运行 Windows 采集实验；ARM 虚拟机不替代 Windows 11 x64 实机证据 |
| 异常与保存 | 产品语义已确认 | 正式代码、故障注入及完整异常验收尚未执行 |

## 进入最终确认前

1. 在现有 Mac 上继续补充其他尺寸/区域的像素对照、屏幕同步及窗口交互证据；可自行操作的步骤由代理完成，需要真人动作或系统协助时明确告知。
2. Windows 实验需要 Intel/AMD Windows 11 x64 设备、摄像头及麦克风，用户确认暂时没有，先完成 Mac 验证与方案，Windows 实机验证暂缓。已发现的 ARM 虚拟机保持挂起，可作为补充环境但不能替代目标实机；不预先承诺结果，也不自动改为仅做 Mac。
3. 依据证据固定各平台最低系统/架构、实际输出尺寸及帧率、SDR/HDR 范围、编码与硬件加速策略、分发渠道和验收机器。公开 API 的最低版本不等于产品已验收的最低版本。
4. 将剩余问题的处理方式列清楚：补验证、收缩支持范围或经用户明确同意延期。不得暗中降低已确认硬要求。
5. 提交可审阅的最终方案、实施顺序和验收清单，再请求用户明确批准正式开发；批准前不创建正式应用骨架、不迁移正式前端、不实现生产录制引擎。
