# Mac 首版正式开发确认稿

版本：2026-09-24。状态：**待用户确认，正式开发未获授权**。

**新增前置条件：先审阅橙色主题 UI 设计稿、选定方向，选稿后再编写并确认 design.md。当前不请求启动开发；选稿不构成正式开发批准。**

前端组件方案：React + TypeScript + shadcn/ui（Radix）+ Tailwind CSS，Lucide React 图标。

这是一份供批准的提案，不是验证全部通过的结论，也不关闭尚未解决的决策议题。建议只先批准下述第一阶段正式整合；第二阶段及分发在第一阶段结果评审后再决定。“继续”、参与测试、同意某项建议，均不自动等于批准。

## 产品范围保持不变

首批面向 Apple Silicon Mac，独立安装包、SDR；Intel、Mac App Store、HDR 延后。Windows 11 x64 保留，因缺少实机暂缓。首次内部验收使用已有 M4 Pro / macOS 26.4，不宣称覆盖全部 M 系列，也不提前承诺最低系统版本。

第一期是本地极简录制界面：单显示器固定录制区域、提词、可选摄像头、麦克风及控制条。屏幕和摄像头各保存一个独立视频；提词、摄像头预览和所有辅助窗口不得进入屏幕视频。正文鼠标穿透，把手和设置可操作。摄像头原片保持设备实际画幅，预览布局不改变原片。

保留 12 个尺寸预设和自定义：

| 比例 | 输出像素（宽×高） |
|---|---|
| 9:16 | 720×1280、1080×1920（默认）、1440×2560、2160×3840 |
| 16:9 | 1280×720、1920×1080、2560×1440、3840×2160 |
| 3:4 / 4:5 | 1080×1440 / 1080×1350 |
| 1:1 / 4:3 | 1080×1080 / 1440×1080 |
| 自定义 | 每边 240–3840 的偶数像素，明确点击应用；非法值不覆盖此前有效值 |

菜单完整保留不等于每台机器已支持全部尺寸。开始前校验实际能力，不可用时说明原因，不偷偷降低尺寸。第一阶段先验收 1920×1080 和 1080×1920 的完整链路；其余预设与自定义仍是第一期要求，不能因本阶段暂未验收而删除。

沿用已确认的倒计时取消、必需设备故障结束整次录制、尽力保存、部分保存提示及退出保护。无服务器，不做视频库、独立剪辑/回放页面、AI、字幕或云同步。不恢复已取消的 30 分钟长录要求。

## 已有什么证据，还缺什么

临时 AppKit 实验在当前机器完成双视频短录、连续三次录制，以及 720 横屏、1080 横屏和竖屏输出检查；文件完整解码、抽查四角和网格比例正常。相机/麦克风有两次真人拍手短录证据。独立交互实验记录了真实鼠标拖动、正文跟随和设置响应。

以下不能写成已通过：

| 未完成项 | 第一阶段如何处理 | 不通过时的边界 |
|---|---|---|
| 跨应用正文穿透、焦点 | 在正式候选窗口结构下做开启/关闭的有效命中对照；工具不能可靠操作时再明确请求人工协助 | 不用“点击调用成功”替代验收，不交付会挡住底层软件的方案 |
| 实际交互与浮窗排除的组合 | 拖动、设置开关及新窗口出现时检查真实屏幕视频 | 不把独立交互和独立录制两份证据拼成联合通过 |
| 屏幕绝对同步 | 保留短录 ±200ms 目标，建立可标定参考及误差说明 | 不用两个文件时长接近或未标定闪白/短音数据冒充通过；无法验收时暂停并报告 |
| 帧率与启动卡顿 | 分别测实际采集间隔、输出帧时间与重复帧；查明现有约 217ms 启动间隔 | 补重复帧不能掩盖采集停顿，不以固定帧率数字宣布流畅度通过 |
| Tauri 与原生桥接 | 用真实原生视频链路整合，不将实验程序冒充正式应用 | 核心路径不成立时停止扩展其余功能并提交取舍 |

这意味着批准第一阶段时，也是在明确同意把上述未解决问题放入第一阶段处理，而不是认可它们已经解决。若不接受该顺序，应继续停留在开发前验证。

## 待批准的帧率建议

屏幕视频建议输出固定 30fps，采集与音频按共同真实时间线对齐；没有新画面时允许重复上一帧，不加速视频、不拉伸音频。摄像头仍按设备实际能力选择采集模式，不静默裁切画幅。文件有 30fps 不代表每秒采到了 30 张不同的新画面，实际卡顿须另外验收。

此建议只定义处理方向。重复帧比例、运动场景的流畅度验收界限仍需在第一阶段提出可复现标准，评审前不作性能保证。

## 建议实施顺序

1. **第一阶段：正式整合和关键风险收口（本次拟批准范围）。** 建立 Tauri 2、React、TypeScript、Rust 正式工程；接入 Mac 原生窗口和采集桥接；以主用横竖 1080 完成权限、区域、提词交互、真实双视频、统一时间线及停止保存的最小完整链路。优先解决上表问题，交付本机可运行内部版本、样片分析、已通过/未通过矩阵及剩余风险。
2. **第一阶段评审。** 展示实际界面和文件，决定是否继续第二阶段。若核心路径失败或支持范围需变化，先给出原因和具体替代方案，不自行减少硬要求。
3. **第二阶段：补齐第一期并交付安装包（不包含在本次拟批准范围）。** 完成所有尺寸/自定义能力检查、设备切换、稿件与偏好保存、异常及退出保护验收；落实系统/机型/显示器支持矩阵、签名公证和安装验证，再准备可分发安装包。Windows 按实机条件另行启动。

首阶段内部验收不等于发布许可。最低系统版本、全部尺寸的实际能力、SDR 色彩、硬件编码与分发条件必须在对外承诺前明确。暂不报缺乏依据的完成日期。

## 本次需要确认什么

是否同意按本稿**启动 Mac 首版第一阶段正式开发**，并接受上述未完成项在第一阶段处理、以结果评审作为进入第二阶段的前提？

建议确认语句：“确认按此稿开始 Mac 第一阶段正式开发。”

在收到明确确认前，仅维护方案和临时实验，不创建正式应用骨架、不迁移正式前端、不实现生产录制引擎。用户可只要求修改确认稿，或要求继续开发前验证；这两种回复均不授权正式开发。
