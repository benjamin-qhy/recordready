# macOS 内测分发与 Sparkle 更新

RecordReady 首期面向 macOS Apple Silicon，沿用海奇AI发布架构中的 Sparkle、ad-hoc 代码签名、独立 Ed25519 更新签名及 HTTPS 静态分发。选择 Sparkle 是为了同时提供完整更新与最近三个已发布版本的增量更新；当前接受首次安装的系统安全确认成本，暂不以 Developer ID 和公证作为内测发布前提。

发布域名为 `recordready.qiushui.me`，与海奇AI共用服务器，但发布目录、更新密钥及应用身份独立。提供下载页和 DMG 首次安装包，后台只检查版本，用户主动下载并确认重启安装；设置页展示版本及更新状态，应用菜单提供“检查更新…”。

准备、倒计时、启动采集、录制、暂停和保存期间不得安装重启，状态未知时同样阻止安装。更新安装必须接入现有原生退出保护，并在最终安装前再次核对会话状态，防止确认期间启动录制产生竞争。

更新包签名不提供稳定的 Apple 开发者身份，升级后的屏幕、麦克风和摄像头权限须以真实升级验收为准。旧版尚未包含更新器，需要手动安装首个具备更新能力的版本；真实升级验收需要两个递增构建及公网更新源。

依据：用户于 2026-09-27 确认首轮全部建议；参考 `haiqiai/docs/architecture/macos-adhoc-sparkle-updates.md`。本决策记录不代表功能已经实现或完成线上验收。

用户随后确认基线为 `0.1.0-beta.1` / `10001`，验收目标为 `0.1.0-beta.2` / `10002`，最终下载页提供 beta.2。下载页采用中英文简洁页面，包括版本、更新说明、首次安装指引和校验值。实施授权包括独立站点部署与 HTTPS 升级验证；服务器连接能力仍须实际核实。
