## 实录与问题修复

完成了横屏 720p（摄像头、麦克风、双 MP4）、竖屏 720p 静音、倒计时取消、提词显示/隐藏、暂停两秒后恢复，以及连续多会话录制。拒绝录制中配置和退出；无效保存目录、消失的显示器有错误返回。

扩展测试覆盖 `1080×1920`、`3840×2160`、`2160×3840`。最初发现 GPU 画布的 4K 竖屏编码没有输出，改为该尺寸使用 CPU 画布，并按会话重建画布上下文。编码器有输出后才进入录制状态，超时明确失败；停止时检查 MP4 顶层容器完整性，只有文件头或截断文件保留 partial，不标记已保存。

MP4 经 FFmpeg 全量解码检查视频和音轨，核对输出尺寸，并独立检查原始视频包时间戳。解码验证为避免 null 输出复用低精度时基而误报，重设**解码输出**时间戳；原始录制文件没有被改写，重复/倒退时间戳另行统计。部分早期 GPU 录制存在少量相同 PTS，不能宣称严格固定帧间隔。

当前使用可变帧率。CPU 4K 竖屏性能明显不足以证明 30fps；4K 支持只是能够生成对应像素的视频。硬件编码、30fps 性能、物理同步 ≤200ms 和三次重复稳定性需按 #5/#7 的标准补齐。Windows 不提供 macOS 原生美颜。

补齐可用 SSH 身份后，执行：

1. 确认 Linux 发布回归通过，检查当前站点及部署锁。
2. 使用 `desktop/windows/deploy.mjs` 上传签名候选，核验字节后原子切换，保留 macOS 内容及不可变归档。
3. 从公网 HTTPS 重新下载并核对 SHA-256、签名和 Range。
4. 用旧版实际检查、下载、延后、确认安装并重启至新版；核对设置/录像以及 macOS 页面和更新源。

当前证据位于被忽略的 `desktop/windows/evidence/`、`.validation/`、`release/published/`。线上验证完成前保留本机候选和旧版包；不把本机候选路径当作已经发布的下载地址。
