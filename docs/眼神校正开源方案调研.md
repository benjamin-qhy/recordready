# macOS 本地眼神校正开源方案调研

调研日期：2026-09-27。范围限定为仓库源码、项目作者发布资料、模型来源及许可证；未下载模型、未安装应用、未执行第三方代码，未上传用户媒体。下列性能均未在本机实测。

## 结论

眼神校正存在本地小模型路线，并不一定需要大模型。两个候选都使用左右眼局部神经网络变形；但目前只能判定为技术验证候选，不能据此保证自然观感、30 fps 或直接商用。对于 RecordReady，可研究将小模型转换并嵌入原生帧处理链，不必安装虚拟摄像头；这是架构建议，尚未实现。

## KypMon/coreml-eye-contact

核查版本：`e9d5ae505c62f87851756e966d3e8d1d39b1bcfe`。

- 主处理器是 Python，使用 MediaPipe 虹膜/面部关键点、ONNX Runtime，优先尝试 CoreML Execution Provider，失败会回落 CPU。名字带 CoreML 不等于全管线原生 Swift，也不代表始终运行在 Neural Engine。[处理源码](https://github.com/KypMon/coreml-eye-contact/blob/e9d5ae505c62f87851756e966d3e8d1d39b1bcfe/neural/engine.py)
- 每只眼输入为 48×64；左右 ONNX 文件分别为 1,061,688 和 1,061,732 字节，总约 2.12 MB。大小来自 Git tree 元数据，未下载权重。[模型目录](https://github.com/KypMon/coreml-eye-contact/tree/e9d5ae505c62f87851756e966d3e8d1d39b1bcfe/neural)
- 首次运行还会下载 MediaPipe `face_landmarker.task`。对源码指定的 Google 官方地址作 HEAD 查询，Content-Length 为 3,758,596 字节。因此模型文件合计约 5.88 MB，不包括 Python、OpenCV、MediaPipe、ONNX Runtime 和系统框架。[下载逻辑](https://github.com/KypMon/coreml-eye-contact/blob/e9d5ae505c62f87851756e966d3e8d1d39b1bcfe/eyecontact.py)、[模型地址](https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/latest/face_landmarker.task)
- 声明依赖：MediaPipe≥0.10.35、OpenCV≥4.13、NumPy≥2、ONNX Runtime≥1.26、syphon-python≥0.1.1。原样接入不属于零依赖原生实现。[requirements.txt](https://github.com/KypMon/coreml-eye-contact/blob/e9d5ae505c62f87851756e966d3e8d1d39b1bcfe/requirements.txt)
- 项目提供 Swift CMIO 虚拟摄像头，需要 Xcode 签名及用户批准 Camera Extension；另有 OBS/Syphon 路线。若只处理自己的录像，可省去该输出层。README 描述了校准、眨眼/转头淡出及眼镜反光导致跟踪抖动的限制。[README](https://github.com/KypMon/coreml-eye-contact/blob/e9d5ae505c62f87851756e966d3e8d1d39b1bcfe/README.md)
- 默认请求 30 fps 是采集参数，源码没有证明本机能持续达到该速度。必须连同面部检测、双眼推理、合成、原有美颜和录制一起测量。[主程序](https://github.com/KypMon/coreml-eye-contact/blob/e9d5ae505c62f87851756e966d3e8d1d39b1bcfe/eyecontact.py)
- 转换脚本将 `chihfanhsu/gaze_correction` 的 TF1 checkpoint 转为 ONNX。仓库当前完整目录中未见 LICENSE，不能把公开可读视为已获得复制分发许可。上游有 BSD 三条款，但不能自动覆盖该仓库新增代码；纳入产品前须澄清新增代码及转换权重的授权链。[转换脚本](https://github.com/KypMon/coreml-eye-contact/blob/e9d5ae505c62f87851756e966d3e8d1d39b1bcfe/neural/convert_to_onnx.py)、[仓库](https://github.com/KypMon/coreml-eye-contact)、[上游 LICENSES](https://github.com/chihfanhsu/gaze_correction/blob/master/LICENSES)

## WangWilly/gaze-correction-cam

核查版本：`a94ec5979b634a7bc812a879a2ebe15ca7d4f6c1`。

- README 声称提供 macOS 14+ 虚拟摄像头应用；公开 master 源码为 Python 摄像头采集、面部定位、TensorFlow 双眼校正、OpenCV 窗口预览。当前目录没有原生 CMIO extension 源码，不能仅凭 README 确认下载版二进制与公开源码完全一致。[README](https://github.com/WangWilly/gaze-correction-cam/blob/a94ec5979b634a7bc812a879a2ebe15ca7d4f6c1/README.md)、[公开目录](https://github.com/WangWilly/gaze-correction-cam/tree/a94ec5979b634a7bc812a879a2ebe15ca7d4f6c1)、[显示与处理循环](https://github.com/WangWilly/gaze-correction-cam/blob/a94ec5979b634a7bc812a879a2ebe15ca7d4f6c1/displayers/dis_single_window.py)
- 依赖 Python≥3.12、TensorFlow≥2.19、dlib、OpenCV、PyObjC、MediaPipe、PyYAML；从源码安装说明另要求 Poetry、CMake、pkg-config。它比原生 CoreML 嵌入路线重。[pyproject.toml](https://github.com/WangWilly/gaze-correction-cam/blob/a94ec5979b634a7bc812a879a2ebe15ca7d4f6c1/pyproject.toml)
- Release 元数据：v0.1.1 的 `weights.zip` 为 5,909,004 字节，`lm_feat.zip` 为 72,326,057 字节；均是压缩包，不是解压后占用。v1.0.1-alpha 的 `GazeAt-Installer.dmg` 为 329,725,065 字节，说明完整交付包远大于眼部模型。未下载这些资产。[Releases](https://github.com/WangWilly/gaze-correction-cam/releases)
- 代码是 BSD-3-Clause，允许遵守通知条款后的再分发；源头为 Chih-Fan Hsu 的研究实现。但默认需要 `shape_predictor_68_face_landmarks.dat`，dlib 官方明确提示该模型训练数据 iBUG 300-W 排除商用，商用模型使用应联系授权方。不能只检查 Python 代码许可证。[项目 LICENSE](https://github.com/WangWilly/gaze-correction-cam/blob/a94ec5979b634a7bc812a879a2ebe15ca7d4f6c1/LICENSE)、[dlib 官方说明](https://dlib.net/face_landmark_detection.py.html)
- 可选 MediaPipe 后端能避开默认 dlib 模型路径，但仍需逐项核查模型分发条件、转换产物及上游训练数据，不应据此宣称所有商用问题已解决。模型来源和原始论文记录在项目自带文档。[源研究说明](https://github.com/WangWilly/gaze-correction-cam/blob/a94ec5979b634a7bc812a879a2ebe15ca7d4f6c1/docs/orignal_doc.md)

## 适用边界与下一步

优先候选是“小眼部模型＋本地关键点＋原生合成”的技术路线，而非原样打包上述 Python 应用。它满足“不让用户额外安装大模型”的可能性；不等于完全没有模型。

尚待验证：小角度读稿的自然度；镜片反射、眨眼和遮挡；头部旋转与低光；眼区分辨率不足时的模糊/拉伸；效果关闭的平滑过渡；与瘦脸/磨皮叠加顺序；1080p30 的持续延迟、发热、功耗。大幅侧看不能预先承诺纠正，眼神校正也不会自动把侧脸变成正脸。

建议先澄清授权，再做独立短时原型；合格后才决定嵌入 RecordReady。当前调研未改动应用代码。
